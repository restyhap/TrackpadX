## 0.1 项目环境事实（本次新增证据）

- **TouchpadBlocker**（gitee，公开仓库，MIT）：
  - 单文件 Swift AppKit 应用（`TouchpadBlockerApp.swift`，~430 行），`swiftc` 直接编译，`build_app.sh` 手工拼装 .app（无 xcodegen / SPM / 无签名 / 无沙盒 entitlements）。
  - bundle ID：`com.resty.touchpadblocker`，LSMinimumSystemVersion 13.0，LSUIElement（菜单栏 app，"TB" 图标）。
  - 核心防误触机制（`TouchpadManager.startMonitoring`）：
    - `CGEvent.tapCreate(tap: .cghidEventTap, options: .defaultTap)` —— **可修改/可拦截型 tap**，回调中对 keyDown/flagsChanged 记录打字时间，对鼠标/滚动事件在打字后 0.5s 内**返回 nil 将事件丢弃**（`handle()` 返回 nil）。
    - 备用通道：`NSEvent.addGlobalMonitorForEvents(matching: [.keyDown, .flagsChanged])`（为中文输入法 IME 提升识别率）。

  - 自动更新（`UpdateManager`）：轮询 Gitee `version.json` → 下载 zip → `/bin/sh` 脚本替换 .app。
  - 设置：自绘 AppKit 窗口（仅 Block Delay 一个输入项）。

## 1. 总体结论

> 2026-10-09 更新：放弃 MAS 后原"硬冲突"全部解除，主链路与防误触拦截可共存于单一直发版。

| 能力 | 技术路径 | 直发（非沙盒）可用性 | 结论 |
|---|---|---|---|
| 全局监听触控板手势（三指状态） | `CGEvent.tapCreate(.cgSessionEventTap, .listenOnly, gesture mask)` + Input Monitoring | ✅ | **可行，推荐路线** |
| 最小化前台应用聚焦窗口 | AX API：`AXUIElementCreateApplication(pid)` → `kAXFocusedWindowAttribute` → `AXUIElementPerformAction(window, kAXMinimizeWindowAction)` | ✅（需 Accessibility） | **可行，推荐主路径** |
| TouchpadBlocker 的"拦截/丢弃 HID 鼠标事件" | `.cghidEventTap` + `.defaultTap` 返回 nil | ✅（非沙盒可创建修改型 tap；现状即此形态） | **原样保留** |
| TouchpadBlocker 的"检测打字时刻" | `addGlobalMonitorForEvents` + keyDown tap（+ Accessibility） | ✅ | 原样保留 |
| 开机自启 | 现行 LaunchAgents 写文件 或 `SMAppService.mainApp`（两者直发均可用） | ✅ | 二选一，技术评估不拍板；LaunchAgents 兼容存量用户 |
| 自动更新 | Gitee version.json + zip 替换 | ✅ | 保留（touchpadblocker 项目已实现可复用） |
| 设置入口 | 应用内"触摸板扩展"属性页（左列功能清单+右侧分支，仿系统设置） | ✅ | 按方案 A 落地（2026-10-09 用户确认） |
| 打包交付 | DMG 安装包签名公证 | ✅ 待落实 Developer ID 证书 | 需 Developer ID 签名+公证，否则首次打开有 Gatekeeper 提示 |

一句话：**放弃上架后两个产品合并为单一直发版全部成立：手势监听、AX 最小化、防护机制三者共存无约束，现有 TouchpadBlocker 的拦截原样保留，自启与自动更新两者选项均开放。**

## 2. 手势识别层评估（新增功能）

沿用 01 文档结论：路线 A（公开手势事件 tap + `NSEvent.allTouches()`），本节补充上架视角：

1. **tap 规格（上架版）**：`CGEvent.tapCreate(tap: .cgSessionEventTap, place: .headInsertEventTap, options: .listenOnly, eventsOfInterest: gesture 类事件 mask)`。注意与 TouchpadBlocker 现行 `.cghidEventTap + .defaultTap` 的三点差异：session 而非 HID（沙盒 listen-only 的规范路径）、listen-only 而非修改型（沙盒唯一可行）、mask 为手势事件族（`.gesture/.beginGesture/.endGesture` 等）而非键鼠事件。
2. **权限**：Input Monitoring（`kTCCServiceListenEvent`），公开 API 预检/申请：`CGPreflightListenEventAccess()` / `CGRequestListenEventAccess()`。手势（含三指 touch 数据）与键盘 keyDown 的 listen 都归属此权限 → 合并后防误触的"打字检测"可复用同一权限。
3. **事件处理约束**：`NSEvent(cgEvent:)` 必须在主线程构造（否则 AppKit 崩溃，AltTab 实证）；tap 回调内不做重活，只入队。这要求新工程按"tap 回调线程投递 → 主线程解析 NSTouch → 后台判定"组织代码，与 TouchpadBlocker 现行"回调里直接处理"的写法不同。
4. **`NSTouch.normalizedPosition` 防护**：Universal Control 间接触摸会抛 `NSInternalInconsistencyException`（ObjC 异常 Swift 捕获不了）。先 `guard touch.isDirect` 再取位置；最大可能性层面加 ObjC try/catch 垫片作为双保险。
5. **性能**：listen-only tap 在 session 层不会阻塞 WindowServer（AltTab #5911 的教训是主动 tap 挂在 HID 层并逐事件处理会拖慢全系统），本路线风险可控。
6. **识别算法不变**（01 文档 6.4 节）：接触数==3 → 质心下移越过阈值 → 冷却一次触发。参数需实机调。

**macOS 27 特有风险（沿用 01 文档 + 本次补充）**：
- macOS 27 收紧的是"**模拟手势事件**"（第三方写入未公开字段伪造 dock swipe 被 WindowServer 忽略），**不涉及"读取真实手势"的 listen-only tap** → 主路线不受冲击；TouchpadBlocker 的"丢弃键鼠事件"也不属于伪造手势，初步判断不受影响（仍列入实机回归清单）。
- 已知 27 beta 存在与事件 tap 相关的过渡动画卡滞 bug（Mac Mouse Fix #1876），观察即可。

## 3. 动作执行层评估：最小化前台应用聚焦窗口

动作定义（用户决策②）："最小化**当前前台应用的聚焦窗口**"（非隐藏整个 App，非退出）。

### 3.1 路线对比

| 路线 | 技术 | 沙盒/MAS | 评估 |
|---|---|---|---|
| **A. AX 动作（推荐）** | `NSWorkspace.shared.frontmostApplication` 取 pid → `AXUIElementCreateApplication(pid)` → `AXUIElementCopyAttributeValue(kAXFocusedWindowAttribute)` → `AXUIElementPerformAction(window, kAXMinimizeWindowAction)` | ✅ 沙盒可用（有 Accessibility 权限即可；上架先例：Magnet 等窗口管理器） | 语义精确等于"点窗口最小化按钮"；窗口有原生 genie 动画；与 Cmd+M 等效 |
| B. 合成 Cmd+M（CGEvent.post 键盘事件） | 伪造 ⌘M 按键发给前台 | ❌ 注入需 kCGHIDEventTap 权限，沙盒无 entitlement，CGEvent.post 被封死 | 排除（这也是 TouchpadBlocker 未来若上架必须放弃的能力） |
| C. AppleScript / Automation | `osascript` tell app "System Events" perform minimize | ❌ 沙盒不支持放宽 Apple Events exception，MAS 不给过 | 排除 |
| D. `NSRunningApplication.hide()` | 隐藏整个 App（Cmd+H 等效），无权限 | ✅ | 语义不符（用户要的是"聚焦窗口最小化"）；仅可作 AX 失败时的降级候选 |
| E. 私有 `CGSManagedDisplaySetCurrentSpace` 类 | — | ❌ 私有 API，MAS 审核必翻车 | 排除 |

### 3.2 AX 路线路径细节与边界

- 权限：**Accessibility（辅助功能）**。注意本功能与防误触现存权限相同，但手势监听权限是 Input Monitoring → **合并产物将需要两个权限**，权限引导页要分别解释、分别深链（`x-apple.systempreferences:com.apple.preference.security?Privacy_Accessibility` 与 `?Privacy_ListenEvent`）。
- "聚焦窗口"取 `kAXFocusedWindowAttribute`；为空时（应用无可聚焦窗口、全屏应用）取 `kAXMainWindowAttribute` 或 `kAXWindows[0]`；仍失败则静默交给系统行为。
- 边界：全屏窗口不可最小化（AX 动作失败）→ 建议失败时降级 `NSRunningApplication.hide()`（无需权限，但语义变为"隐藏"），该策略列入待实测确认项，不在本文档拍板。
- 触发时机：三指手势 `ended` phase 后执行一次（冷却防重），避免滑一半误触发。

### 3.4 与系统手势的并发（重要）

listen-only tap 返回事件不等于"系统不认识这个手势"——三指下滑在系统设置里默认映射 **App Exposé**（可选三指或四指）。用户三指下滑时：我们的最小化 + 系统的 App Exposé 会**同时**发生。listen-only 无法吞掉系统识别（01 文档已论证）。缓解：
- 设置页面对该手势标 ⚠️ 并提供深链让用户把触控板设置的 App Exposé 改为"四指"或关闭；
- 或默认推荐用户改用四指下滑（系统占用弹度低）。
- 该冲突的实测（macOS 27 上 tap 能否与系统手势和平共存、App Exposé 实际默认值）列入最小原型验证清单（01 文档第 8 节已列）。

## 4. TouchpadBlocker 合并评估

### 4.1 合并对象现状 vs 新工程要求

| 维度 | TouchpadBlocker 现状 | 新工程要求（决策①②③） | 迁移工作量 |

| 打字检测 | `addGlobalMonitorForEvents` + `keyDown` tap | 沙盒内 listen-only keyDown tap 同权限覆盖 | 可迁移 |

### 4.2 核心冲突解除（2026-10-09 定案）

原冲突是"TouchpadBlocker 拦截式防误触 vs 沙盒"。**用户已放弃 MAS（决策①变更），冲突不复存在。**

定案：**合并为单一 Gitee 直发 App，TouchpadBlocker 拦截逻辑原样保留**，三选一中即原方案 3（当时因决策①列出仅供参考，现决策①变更后成为正式选择）：

- 无需双构建目标、无需条件编译切 Feature 清单；
- 最新 macOS 上 listen-only 手势 tap 与 cghidEventTap 拦截 tap 可并存（两个 tap 各司其职，仍列入实机回归）。

### 4.3 架构建议（可扩展多功能列表，对齐决策③）

参考用户 StatusMaster 的模块划分，目标结构（**仅方向示意，本期不实施**）：

```
App/           AppDelegate、依赖装配
Schema/        FeatureDescriptor 协议：id/title/icon/toggle/MaskedView(isEnabled/permissionState)
Services/
  GestureListenerService    CGEventTap listen-only（session 层，gesture mask）
  GestureRecognizers/       ThreeFingerDownRecognizer（接触数+质心位移状态机）
  MinimizeWindowService     AX kAXMinimizeWindowAction
  TypingDetectionService    addGlobalMonitorForEvents + keyDown（沿用 TouchpadBlocker 现行）
  TouchpadBlockerService    现 cghidEventTap 拦截逻辑迁入
Views/         设置主窗口：左侧 Feature 列表 + 右侧各 Feature 设置面板；权限引导页（Accessibility 为主）
Store/         UserDefaults/Codable 持久化
Utils/
```

- 每个 Feature 独立声明所需权限，权限预检失败在 UI 上挂黄标并可一键跳设置。
- 单一直发目标（2026-10-09 定案），无需双 target 与条件编译。
